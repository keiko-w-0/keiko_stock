# Keiko Stock AI 调研与实施报告

调研日期：2026-06-05  
目标：做一个可安装在 MacBook 上的本地股票 AI 研究软件，覆盖 A 股、港股、美股的每日观察、关注池复核、手动个股分析，并显式降低数据过期、资讯误判和 AI 幻觉风险。

## 1. 结论摘要

这个产品最关键的不是“让 AI 更会猜”，而是让 AI 在数据不够、来源不稳、证据冲突时主动拒绝下结论。推荐把系统拆成四层：

1. 数据层：行情、K 线、财务、估值、资金流、公告、新闻、情绪。
2. 校验层：实时性检测、跨源一致性、官方公告优先、异常值检测。
3. 策略层：用规则和因子先产生候选，再让 AI 做解释、反驳和风险归纳。
4. 反思层：最多 3 轮，每轮有明确 rubric，失败则降级为“观察/无法判断”。

真实版本必须接受一个现实：高实效、准确、可交易级别的实时行情通常需要授权数据或付费数据源。免费接口适合原型和研究，不适合直接驱动交易。

## 2. 数据源分层建议

### A 股

推荐组合：

- 行情/K线/基础财务原型：Tushare Pro、AKShare。
- 官方公告和财报核验：巨潮资讯 CNINFO、上交所、深交所。
- 交易日历、停复牌、ST、退市风险：交易所公告 + 数据商补充。

说明：

- Tushare 覆盖 A 股基础资料、行情、财务等接口，适合做结构化数据主源。
- AKShare 覆盖大量公开金融数据，适合原型和备份，但要把它视作“聚合/抓取接口”，需要校验。
- A 股上市公司公告应优先以 CNINFO、上交所、深交所为准。

### 港股

推荐组合：

- 行情/K线：付费行情供应商优先；原型可用 Tushare/AKShare/Alpha Vantage/Finnhub 等做延迟数据。
- 官方公告：HKEXnews。
- 基本面：公司年报、HKEXnews 披露、数据商结构化财务。

说明：

- 港股行情如果要接近实时，最好走授权数据商。
- 公司动作、停牌、配股、回购、业绩公告等，应以 HKEXnews 和公司公告为核心证据。

### 美股

推荐组合：

- 行情/K线：Polygon/Massive、Finnhub、Alpha Vantage、Tiingo、Intrinio 等。
- 官方财报和重大披露：SEC EDGAR API。
- 公司新闻/情绪：Alpha Vantage News Sentiment、Finnhub Company News、主流财经媒体，外加 SEC/公司 IR 核验。

说明：

- 美股数据生态成熟，但“免费层级”通常有频率、延迟、交易所覆盖限制。
- 基本面和重大事件尽量回到 SEC EDGAR 或公司 IR 页面核验。

## 3. 数据实时性检测

每一条数据进入系统时都必须带 metadata：

- `provider`：数据提供方。
- `market`：A/HK/US。
- `symbol`：标准化 ticker。
- `fetched_at`：本机实际拉取时间。
- `as_of`：数据自身对应的市场时间。
- `market_session`：盘中、午休、收盘后、休市。
- `expected_delay_sec`：该数据源可接受延迟。
- `source_url` 或 `request_id`：追溯入口。
- `checksum`：用于判断重复和缓存污染。

建议实时性规则：

- 盘中分钟/逐笔行情：`now - as_of <= 90 秒` 才标为 fresh；付费延迟源按合约延迟设置。
- 日 K：交易日收盘后应在 T+0 或 T+1 到位；超过一个交易日标黄，超过两个交易日标红。
- 财务和估值：以最近一期财报/公告为准；如果估值依赖行情，必须同时检查行情新鲜度。
- 新闻和公告：公告源优先；新闻超过 72 小时仍用于“情绪”时要降权，不能当作新催化。

失败处理：

- 数据过期：不生成买入/卖出结论，只给“观察/需刷新”。
- 拉取失败：显示失败来源和 fallback 来源，禁止 AI 编造。
- 多源冲突：超过容忍阈值时进入人工复核队列。

## 4. 真实性判断

把资讯拆成可验证 claim，而不是把整篇新闻丢给 AI 总结。

来源等级：

- S 级：交易所、监管披露、SEC EDGAR、HKEXnews、CNINFO、上交所、深交所。
- A 级：公司 IR、正式业绩会材料、审计报告。
- B 级：主流财经媒体、授权数据商新闻。
- C 级：社媒、论坛、自媒体、传闻。

真实性流程：

1. 抽取 claim：例如“公司宣布回购”“利润同比增长”“大股东减持”。
2. 绑定证据：每个 claim 至少有 source、发布时间、原文链接、实体匹配结果。
3. 交叉核验：重大公司动作需要 S/A 级来源；只有 B/C 级则标为“未证实”。
4. 冲突检测：同一事件如果金额、日期、主体不一致，降低可信度。
5. 时效降权：旧新闻不可作为当前催化，除非有后续公告确认。

## 5. 情绪面分析

情绪面只能作为辅助，不能单独触发买入。

可组合信号：

- 新闻情绪：FinBERT 或数据源自带 sentiment score。
- 新闻热度：同一事件的报道数量、传播速度、来源等级。
- 市场确认：成交额放大、跳空、波动率、行业同涨。
- 资金流：北向/南向、ETF 资金、机构持仓变化。
- 分析师和预期：评级变化、盈利预期修正、业绩预告。
- 社媒：只作为低权重噪声或异常提醒。

建议把情绪输出为：

- `sentiment_score`：-100 到 100。
- `sentiment_confidence`：0 到 1。
- `dominant_topics`：主要话题。
- `unverified_ratio`：未证实信息占比。

如果 `unverified_ratio` 高，AI 必须降低结论强度。

## 6. 选股策略框架

先用规则生成候选，再由 AI 解释，不让 AI 从空白处“幻想股票”。

### 股票池过滤

- 流动性：成交额、换手率、买卖价差。
- 交易状态：停牌、退市风险、ST、极端涨跌停。
- 基本面可用性：至少有最近一期财报或可靠估值数据。
- 风险排除：重大诉讼、监管处罚、审计保留意见、持续经营风险。

### 因子模块

- 基本面：营收/利润增长、ROE/ROIC、毛利率、现金流、负债率。
- 估值：PE/PB/PS/EV/EBITDA 与行业和历史分位对比。
- 技术面：趋势、均线、突破、成交量、ATR 波动。
- 催化：业绩、回购、订单、政策、产品发布、行业周期。
- 资金面：北向/南向、机构持仓、ETF、融资融券。
- 情绪面：新闻情绪、热度、未证实比例。
- 风险面：波动、回撤、治理、政策、黑天鹅。

### 输出动作

不要直接输出“无脑买入”。建议动作分级：

- `重点观察`：分数高，但等待确认或入场价。
- `小仓试探`：数据新鲜、证据充分、风险收益比达标。
- `持有复核`：趋势和基本面未破坏。
- `减仓观察`：风险升高或核心假设被削弱。
- `退出/回避`：数据失真、证据冲突、基本面恶化或技术破位。
- `无法判断`：数据不足或过期。

## 7. AI 反思 Rubrics：最多 3 轮

反思不能无限循环，也不能偷偷消耗 token。建议固定最多 3 轮，并把结果展示给用户。

### 第 1 轮：数据闸门

问题：

- 关键行情是否新鲜？
- 财务/估值是否来自可靠来源？
- 是否存在拉取失败、缺字段、异常值？
- 市场是否正在交易，延迟规则是否匹配？

失败动作：

- 直接降级为“无法判断/需刷新数据”。

### 第 2 轮：证据闸门

问题：

- 每个重大 claim 是否有证据？
- 重大公司动作是否来自 S/A 级来源？
- 新闻与公告是否冲突？
- 情绪面是否被未证实传闻主导？

失败动作：

- 降低可信度；只允许输出观察，不允许输出买入/卖出。

### 第 3 轮：投资逻辑闸门

问题：

- 买入理由是否同时有基本面、技术面或催化支撑？
- 卖出理由是否区分短期波动和核心假设破坏？
- 风险收益比是否足够？
- 是否给出了反方观点、失效条件、止损/复核点？

失败动作：

- 降级动作强度；输出“等待确认”或“人工复核”。

停止规则：

- 3 轮后必须停止。
- 如果任一轮发现硬失败，提前停止。
- 如果连续两轮结论无变化，不再重复反思。

## 8. 本地软件架构

推荐技术路线：

- 前端：HTML/CSS/TypeScript 或 React。
- 本地后端：FastAPI。
- 数据库：SQLite 起步，后续加 DuckDB/Parquet 存历史数据。
- 任务调度：APScheduler 或系统 launchd。
- Mac 包装：Tauri 优先，Electron 作为备选。
- 密钥：macOS Keychain，不写入明文配置文件。

核心模块：

- `providers/`：行情、财务、公告、新闻供应商适配器。
- `data_quality/`：实时性、schema、异常值、跨源一致性。
- `claims/`：资讯 claim 抽取、证据绑定、真实性评分。
- `strategy/`：因子打分、候选生成、买卖复核。
- `llm/`：只接收结构化数据和证据，不直接联网瞎猜。
- `audit/`：保存每次分析的数据快照、prompt 摘要、反思结果。

## 9. MVP 开发路线

### 第 0 阶段：当前 mock 原型

- 每日候选池。
- 关注池分析。
- 输入 ticker 分析。
- 数据新鲜度和来源可信度 UI。
- 最多 3 轮反思 UI。

### 第 1 阶段：真实数据最小闭环

- 接入一个市场优先，例如美股。
- K线、基本面、SEC 公告、新闻情绪。
- 实现数据缓存和新鲜度检查。
- AI 只基于证据生成解释。

### 第 2 阶段：A/HK/US 多市场

- A 股：Tushare + CNINFO/交易所公告。
- 港股：HKEXnews + 行情供应商。
- 美股：Polygon/Finnhub/Alpha Vantage + SEC EDGAR。
- 标准化 ticker、币种、时区、交易日历。

### 第 3 阶段：Mac 安装版

- Tauri 打包。
- 本地数据库迁移。
- API key 配置和健康检查。
- 每日自动扫描和通知。

## 11. 交互增强设计

### 股票池过滤

过滤器不应该只有固定策略，也不应该完全交给自然语言。推荐双入口：

- 显式组合：用户勾选成交额、换手率、买卖价差、PE 分位、ROE、趋势、量能、催化、证据可信度等规则，并选择“全部满足/任一满足”。
- 自然语言入口：用户输入“成交额高、价差小、趋势强、证据可信度高”，系统先转成明确规则，再展示给用户确认。

真实版本中，自然语言只负责生成候选过滤规则，最终执行必须落到可审计的结构化条件，例如：

```json
{
  "mode": "all",
  "rules": [
    {"field": "avg_amount_cny_20d", "op": ">=", "value": 5000000000},
    {"field": "spread_bps", "op": "<=", "value": 5},
    {"field": "ma20_gap_pct", "op": ">", "value": 0}
  ]
}
```

### 分析记忆

记忆不能保存成“估值偏高”“情绪不错”这种笼统句子。推荐保存为结构化中间结果：

- 实体与业务画像：ticker、市场、币种、行业、主营业务、公司别名、重要子公司。
- 归一化财务基线：收入、利润、ROE、现金流、负债率、财报期、计算口径。
- 已验证 claim 索引：claim 文本、来源等级、链接、发布时间、实体匹配、置信度。
- 因子计算快照：每个因子的原始字段、归一化值、评分、权重、失效条件。
- 上次结论和反方观点：动作、核心假设、风险、触发复核的条件。

可复用：

- 公司静态画像、历史财务基线、已验证且未过期的公告 claim、上次因子计算方法、上次反方观点。

必须重新拉原数据：

- 行情、K 线、成交额、换手率、买卖价差。
- 最新公告、停复牌、减持、回购、业绩预告。
- 新闻情绪、社媒热度、未证实比例。
- 依赖最新价格或最新财报口径的 PE/PB/PS 等估值字段。

第二次分析流程：

1. 读取结构化记忆。
2. 拉取增量数据。
3. 判断哪些记忆仍可复用，哪些因新数据失效。
4. 只对新增数据和失效模块重新分析。
5. 更新记忆，并保留旧版本审计记录。

### 低置信原因与用户补证据

每个“当前结论不置信”的原因都要绑定可操作动作：

- 数据过时：显示过时数据类型、延迟分钟数、供应商、上次拉取时间，并提供刷新按钮。
- 论据不足：显示缺少哪类证据，允许用户粘贴公告、新闻、研报摘要或链接。
- claim 冲突：列出冲突字段，例如金额、日期、主体、事件类型。
- 因子冲突：例如强催化但高估值、基本面强但技术破位，要求查看因子详情。

用户补充证据只能先进入“待核验证据”，不能直接替代官方披露。系统应重新做实体匹配、来源等级评估和时效检查后，再更新结论。
